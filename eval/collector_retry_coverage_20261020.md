## Recovery behavior

1. **Known failed downloads:** atmos makes bounded per-repository attempts, then calls Jetstream `OnFail`; ordinary failures persist `StatusFailed`, error, attempt count and host in metadata. The failure log precedes the store callback, so a log line by itself is not durable-record proof. Jetstream's [steady-state loop](https://github.com/bluesky-social/jetstream/blob/d4db8c08eb887dd148cd7c1d5f4a9fb327e15f06/internal/ingest/orchestrator/steady.go#L131-L146) starts only after bootstrap and merge. Its [retry scanner](https://github.com/bluesky-social/jetstream/blob/d4db8c08eb887dd148cd7c1d5f4a9fb327e15f06/internal/ingest/backfill/retry.go#L395-L419) selects active failed rows whose persisted next-attempt time is due. Later failures receive durable backoff, capped at seven days. It does not guarantee all errored rows receive attempts before this run ends.
2. **Pending rows:** merge performs a separate one-shot retry pass after replaying the captured live tail, before its final discovery scan. This protects replacement ordering after bootstrap interruptions. Pending is not selected by the ordinary steady-state failed-row scanner. Failed pending-pass work can transition to failed and become eligible later. See [merge ordering](https://github.com/bluesky-social/jetstream/blob/d4db8c08eb887dd148cd7c1d5f4a9fb327e15f06/internal/ingest/orchestrator/merge.go#L115-L151).
3. **Exhausted PDS hosts:** a PDS is a server hosting account repositories. atmos keeps exhausted hosts terminal for that engine run and preserves the last successful enumeration cursor; failed pages do not advance it. Jetstream records `Enumerated=false`, so another bootstrap engine run can revisit the host from its saved cursor. **This is restart capability, not an automatic restart instruction.** A restart also defers older `not_started` work into pending, so it is not a simple immediate retry of every known failed DID.
4. **One more host pass in this same job:** unless discovery is skipped, merge reopens hosts from their last nonempty bootstrap cursor. It makes three host attempts with bounded backoff. Newly discovered DIDs receive failed-row markers for later retry. The source explicitly documents **report and proceed** if a host exhausts again: its never-listed DIDs have no marker rows and steady state has **no enumeration sweep**. See [HostDiscoveryCursors](https://github.com/bluesky-social/jetstream/blob/d4db8c08eb887dd148cd7c1d5f4a9fb327e15f06/internal/ingest/backfill/store.go#L1344-L1359) and [merge discovery policy](https://github.com/bluesky-social/jetstream/blob/d4db8c08eb887dd148cd7c1d5f4a9fb327e15f06/internal/ingest/orchestrator/merge_discovery.go#L40-L101). Live events may reveal later activity but do not establish historical repair of those unlisted repositories.

The supervisor was active; Drive drain timer/service and old offloader were inactive. The uploader was advancing. These facts establish productive preservation only.

**No reliable completion ETA follows from these snapshots.** The job was still in bootstrap; merge duration, the pending retry pass, per-host throttling and per-row retry eligibility are unknown. The existing job has built-in opportunities to repair known failures and revisit host enumeration if it reaches those phases before the deadline, but it cannot be represented as guaranteed to do so. A host still exhausted after merge has no scheduled later enumeration repair in this deployment.

No immediate decision is needed for continued observation within the already-authorized cap and stop deadline. After the bounded run, preserve the remaining failed/pending counts, exhausted-host roster/cursors, image identity and phase as repair inputs. **Any additional run, restart, concurrency change or budget extension requires a separately approved repair scope.** Recommended decision at that point: authorize a bounded recovery plan aimed at retained known failures and unresolved enumeration tails, with explicit request pacing, cost/duration limits and before/after coverage evidence. Until authorized, keep the existing stop and all graph/Drive holds unchanged; do not call the archive complete.
