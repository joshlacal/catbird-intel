This change repairs the local community recommendation API so its output no longer presents invented outcomes, caller-supplied authentication, or heuristic score cutoffs as measured product behavior. It separates follow actions, Catbird repost preferences, and topic-feed intentions, and returns post identifiers for viewer-aware hydration. The candidate passed 30 actual loopback HTTP assertions, 22 focused tests, and TypeScript checking; none of these checks contacted ClickHouse or production. ## What changed

- **One honest control contract.** [serving_contract.ts](/Users/joshlacalamito/Developer/Catbird+Petrel/catbird-intel/src/serving_contract.ts:1) defines `catbird.intel.serving.v2`. Health filtering is off unless the caller explicitly requests `baseline_score_cutoff`. Feed and preview call the same predicate and report the same policy semantics. The cutoff is an uncalibrated legacy numeric diagnostic, never a probability or exposure-share budget. Missing, zero-default, nonfinite, negative, and out-of-range scores remain unknown; unknowns are included and their observed share is reported. An empty result reports a null unknown share.
- **Invented outcomes removed.** The API and diagnostics no longer emit `predicted_mix`, `realized_mix`, or `realized_7d` results. Legacy event-volume and old health controls return a 400 error rather than silently changing meaning. The source no longer describes the fixed swipe update as Thompson/BALD inference, nor the two-pass selection as an optimized portfolio.
- **Typed, review-only delivery actions.** [serving_contract.ts:73](/Users/joshlacalamito/Developer/Catbird+Petrel/catbird-intel/src/serving_contract.ts:73) and [api.ts:885](/Users/joshlacalamito/Developer/Catbird+Petrel/catbird-intel/src/api.ts:885) return `follow_account` with optional `client_preferences: {scope:"catbird", hideReposts:true}`, or `topic_feed_intent` with `follow:false`. Topic-feed intentions never enter the follows array. These choices are explicit caller preferences, not deductions from author health scores. Every action is `applied:false` and `executable:false`; no account mutation or client preference was executed. Repost hiding does not promise removal of replies or quote posts.
- **Identifier-only recommendation payloads.** Feed, community posts, scene-card samples, calibration samples, and preview posts return `{post: atUri}`. Community metadata omits top account identifiers; account references return DIDs without inferred political profiles. Feed and starter-pack ownership receives the same cached visibility checks as account suggestions. `getAuthorModes` exposes aggregate diagnostics only. Debug requests do not enable raw post text. Curated scene labels remain editorial metadata.
- **Trust comes from the service token.** [service_auth.ts](/Users/joshlacalamito/Developer/Catbird+Petrel/catbird-intel/src/service_auth.ts:22) validates signed inter-service JWTs using a caller-injected trusted DID-document key resolver, an exact audience including its service fragment, endpoint `lxm`, issuer DID, allowed `#atproto` key purpose, ES256/ES256K algorithm, issued/expiry times, and a one-time nonce. Missing authorization is logged out; invalid or unconfigured authorization is 401. Query/body `unauthenticated:false` never authenticates. A requested feed actor must equal the verified viewer. Cache publication is not an authenticated public API.
- **Explicit version and readiness limits.** [api.ts:146](/Users/joshlacalamito/Developer/Catbird+Petrel/catbird-intel/src/api.ts:146) returns a contract version and the source community version, but `derived_generation:null` because other derived tables cannot yet be bound to the same generation. `/health` explicitly says `ready_for_public_promotion:false`. The visibility/profile reads now use `FINAL`; refresh failure does not publish an empty permissive restriction set. This does not make the retained prior cache current or deletion-reactive.
- **Legacy telemetry writes disabled.** [api.ts:947](/Users/joshlacalamito/Developer/Catbird+Petrel/catbird-intel/src/api.ts:947) cannot insert into historical telemetry tables. Omitting invented fields while retaining the old persistence target would still leave incompatible columns/defaults in use. Feed diagnostics now contain the explicit control report and unknown coverage, rather than unqualified `political_share` or `mean_heat`. Buffers retain at most 1,000 events each in process memory, and the API reports persistence disabled pending a versioned schema migration. This intentionally provides no durable product measurement.
- **Input boundaries and fixture seam.** The API can be imported without starting a server, cache refresh, or database query. A snapshot injection function supports local HTTP tests. Requests validate limits, six-point allocation totals, known scenes, offered swipe identifiers/pairs, typed preferences, JSON shape, and body size. Direct execution binds localhost by default and starts with authenticated serving unconfigured.

## Remaining promotion blockers and concrete next work

1. **Live eligibility and deletion state.** The current cache still lacks a current per-object deletion/account-state overlay, external labeler handling, viewer blocks/mutes, reference-list semantics, and bounded freshness failure policy. Cached `FINAL` reads address deduplication at refresh time only. Implement the protocol review's overlay and reconciliation contract, prove keyed deletion-to-hidden delay, and keep unknown lifecycle state ineligible. A current-state failure must not indefinitely serve an old permissive generation.
2. **One derived-data generation.** Community membership, candidate posts, directory entries, author aggregates, affinities, and policy data currently cannot be atomically pinned to one manifest. Add immutable generation manifests, build/validate all parts before publication, pin onboarding sessions, and require an explicit expiry/restart result instead of mixing versions. Restore/rollback must preserve the live restriction overlay.
3. **Production authentication wiring.** No production audience or DID resolver is configured. The local nonce cache is process-local and disappears on restart; distributed replay protection, resolver caching/rotation and error policy, bounds/rate limits, and production token interoperability remain unqualified. The local policy additionally requires a maximum 60-second lifetime and no future issued-at skew; these are explicit candidate choices, not claims that every conforming ecosystem token uses them. Official baseline: [AT Protocol inter-service authentication](https://atproto.com/specs/xrpc#inter-service-authentication-jwt).
4. **Client hydration and actions.** Catbird must hydrate every identifier through the viewer's AppView and apply session labelers, blocks/mutes, adult eligibility, and embed/thread policy. It must display reviewable actions, execute follows through the authorized account, persist Catbird repost preferences, and implement a concrete topic feed before any intent becomes executable. Verify the actual native UI and resulting behavior on a simulator/device with an approved test account.
5. **Telemetry migration and product measurement.** Create a versioned event schema with source/generation/policy provenance and explicit coverage denominators; retain historical invented outcomes as invalidated artifacts, not observations. Re-enable persistence only after migration and writer/reader compatibility tests. Actual exposure and seven-day retained-and-exposed outcomes require client instrumentation and a prospective cohort; response counts are not exposure.
6. **Quality qualification.** Current scene calibration, account selection, and feed ranking remain heuristics. No learned student is wired into serving, no causal control effect is measured, and no recommendation or moderation accuracy follows from these tests. Editorial review and the frozen human/real-data evaluation gates remain required.

These are production promotion blockers, not unreported successful work. The local correction is reviewable and runtime-tested within its explicit boundary; no production deployment or security configuration change is authorized by this memo.
